App Access

        
Reported grants and sandbox capabilities for installed apps. An unknown or missing entry is not the same as denied. Apps start collapsed; click one to expand its grants.

      

      

        
        
      

    

    

    

      
      
      
      
      
      
    

    

    
Select App Access to load inventory.

    

      What can actually be deleted here: only rows with an
      Unload & delete or Delete button — third-party
      launchd jobs in /Library/LaunchDaemons and /Library/LaunchAgents, and helper binaries in
      /Library/PrivilegedHelperTools. Those locations are user-writable with administrator
      approval. Items without a button (or whose Remove fails with a system-protection error)
      are protected by macOS and cannot be removed from any app while System Integrity
      Protection is enabled.
      

      Unload & delete (orange) is for launchd jobs — LaunchDaemons and
      LaunchAgents: it first unloads the job from launchd (stopping the running process so it
      does not just respawn) and then deletes the plist file.
      

      Delete (orange) is for bare helper binaries in
      /Library/PrivilegedHelperTools: those are plain executables, not launchd jobs, so there is
      nothing to unload — the file is removed directly. If a daemon still points at a deleted
      helper, remove the daemon too, or launchd will simply fail to start it.
      

      Remove (red) deletes a user TCC grant row after saving a backup. Sentinel
      must have Full Disk Access to enable it. System-database TCC rows are SIP-protected:
      even root cannot modify that file, so system grants cannot be removed from here —
      for those, sudo tccutil reset is Apple's supported route.
      

      tccutil caveat: tccutil reset <Service> <bundle-id>
      only works for apps LaunchServices still knows (it fails with error -10814 for
      uninstalled/leftover entries), and tccutil reset <Service> without a
      bundle id cannot target one app — it resets all apps' preferences for that
      service (every app re-prompts on next use).
      

      Sentinel is configured for AppDeck's Elevated launch so its own app identity can receive
      that access. Every action here also exists as a terminal command — see Firewall Rules for
      firewall-specific commands.
    

  


  

    

      

        
Live Access

        
Apps holding or attempting access to the microphone, camera, password-manager data or sensitive files right now — Sentinel's own per-OS scan plus AppScope Monitor's privacy events (camera/mic use the local scan can't see, e.g. without Full Disk Access), refreshed every fast tick. Apps start collapsed; click one to expand its accesses. Each expanded row has a popup on/off button that silences alerts for that one app+file pair only — the app's other files still alert. Recently-used rows (TCC, consent store, monitor events) carry a timestamp instead of a "live" badge. The summary tiles filter the list; "live right now" toggles the live-only filter.

      

      

        
      

    

    

    

      
      
      
      
      
      
    

    

    
Select Live Access to scan.

    

      What this shows: every app currently holding a capture device
      (/dev/video*, ALSA/OSS audio), a password-manager store (1Password, Bitwarden,
      KeePass, pass, Kwallet, keyrings…), or an open file under your
      sensitive_paths rules — plus per-app camera/mic recent use from macOS
      TCC timestamps and the Windows CapabilityAccessManager consent store (including
      apps that keep asking while Windows answers "Deny").
      

      Who gets alerted: camera/mic use (higher when the same app holds a
      public outbound connection), password-manager data read by anything outside the
      manager family, and sensitive files held alongside a public connection. Browsers and
      updaters (quiet_apps) and system indexers/backup services are listed
      but not alerted. Windows has no supported per-app open-file enumeration —
      file/password-manager rows there need AppScope Monitor file events.
    

  


  

    

      

        
Exclusions

        
Per-app silences. Watchdog stops that app's alerts and notifications entirely (they are never recorded); Auto-ack keeps recording the app's alerts (history + hit counts) but lands them pre-acked — no popup, hidden by "hide acked"; Live Access and App Access hide the app from those tabs. Matching is case-insensitive by name, so "zcode" also covers "ZCode Helper". Apps with unacked watchdog alerts are listed first with a watchdog firing badge — each alert row also has 🔕 exclude and 🤫 auto-ack buttons that silence its app in one click. Below an app you'll also find its per-target exclusions (one file of that app only — set from Live Access's popup button). Rows for apps no current scan sees — probably uninstalled — are hidden from this list (their exclusions keep working; the row returns if the app shows up in a scan again); the Not seen (uninstalled) state filter reveals them for review, and Remove not-installed purges them for good.
